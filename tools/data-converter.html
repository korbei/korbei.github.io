JSON, YAML, and TOML are three ways of writing the same thing: structured data made of objects, arrays, strings, numbers, and booleans. Each has its niche — JSON dominates APIs and web payloads, YAML is popular for configuration and CI pipelines, and TOML is the format of choice for many modern language toolchains. This converter translates between all three, live, in your browser.

Because the three formats share a common data model, converting between them is lossless for the values themselves: an object becomes a mapping becomes a table, an array becomes a sequence, and scalars carry across unchanged. Comments are the exception — JSON has none, so converting a commented YAML or TOML file to JSON drops the comments, and there is nowhere to recreate them on the way back.

Conversion happens as you type, with clear errors when the source is malformed. Nothing is uploaded, so you can safely convert configuration files that contain internal hostnames or other private details.

When to use each format

JSON
Ubiquitous for APIs and data interchange. Strict, no comments, quotes required — great for machines, less friendly to hand-edit.
YAML
Indentation-based and comment-friendly. Common for CI/CD, Kubernetes, and app config where humans edit by hand.
TOML
Explicit and unambiguous with clear tables. Favoured by Rust (Cargo), Python (pyproject), and other tooling. Requires an object at the top level.

Frequently asked questions

Is the conversion lossless?+

Values, structure, and types round-trip faithfully between all three formats. The one thing that cannot survive is comments: JSON has no concept of them, so any comments are lost when converting through or to JSON.

Why can’t my data convert to TOML?+

TOML requires a table (object) at the top level. A document whose root is a bare array or a single scalar has no valid TOML representation, so those inputs can convert to JSON and YAML but not to TOML.

How are dates and numbers handled?+

JSON has no native date type, so dates become strings. YAML and TOML do understand dates and typed numbers, and the converter preserves them where the target format supports them and falls back to strings where it does not.

Does it validate my data against a schema?+

No — this tool converts between formats. If you need to validate JSON against a JSON Schema or pretty-print a single format, use the Code Formatter instead.
